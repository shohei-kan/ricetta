# Ricetta MVP Requirements

## MVPの目的

Ricetta のMVPでは、小規模飲食店がレシピ・材料・原価・今日の仕込みを管理できる最小限のWebアプリを作ります。

目的は、以下の体験を検証することです。

> 紙・Excel・ホワイトボードに散らばっていたレシピと仕込み情報を、現場で使える形に整理できるか。

## MVPの到達目標

MVPで達成したい状態：

- Ownerがログインできる
- 店舗ごとにデータが分離されている
- レシピを登録・編集・閲覧できる
- 材料・分量・単価を登録できる
- レシピごとの材料原価を計算できる
- 今日の仕込み一覧を確認できる
- 仕込みタスクを完了にできる
- スマホ・タブレットで主要画面が見やすい
- タブレット横向きで、現場閲覧に使える

## ユーザー種別

MVPではユーザー種別をシンプルにします。

### Owner

店舗の管理者です。

できること：

- ログイン
- レシピ登録・編集
- 材料登録・編集
- 原価情報の閲覧
- 今日の仕込み作成・更新
- 設定管理
- Staff用アカウントの管理は将来対応

### Staff

店舗スタッフです。

MVPでは公開デモ前の最小制御として、現場操作と管理操作を分けます。

できること：

- レシピ閲覧
- 材料閲覧
- カテゴリ・単位の参照
- 今日の仕込み閲覧・作成
- 仕込みタスクのステータス変更
- BoardMemo追加・チェック・未チェック戻し
- 自分の表示名編集

できないこと：

- レシピ登録・編集
- 材料登録・編集
- カテゴリ・単位の作成・編集・削除
- 店舗情報編集

将来的な想定：

- 原価情報は非表示にできる

高度なStaff権限管理は後から拡張できるようにします。

## MVP対象機能

### 1. ログイン

Ownerがログインできるようにします。

MVPでは、メールアドレスとパスワードによるログインを想定します。

機能：

- ログイン
- ログアウト
- ログイン中ユーザーの取得

API例：

- `POST /api/v1/auth/login/`
- `POST /api/v1/auth/logout/`
- `GET /api/v1/auth/me/`

### 2. 店舗アカウント

すべての主要データは店舗に紐づけます。

MVPでは、1ユーザーが1店舗に所属するシンプルな形で始めます。

ただし、将来のSaaS化に備えて、`shop_id` による店舗スコープを必ず持ちます。

### 3. レシピ登録

レシピを登録できます。

登録項目：

- レシピ名
- カテゴリ
- 説明
- 基準量
- 基準単位
- 材料
- 分量
- 作り方
- 注意点
- アレルゲン
- 販売価格
- 写真

MVPでは写真アップロードは簡易実装でも可とします。

### 4. レシピ一覧

店舗内のレシピを一覧表示します。

表示項目：

- レシピ名
- カテゴリ
- 基準量
- 写真
- 更新日

操作：

- 検索
- カテゴリ絞り込み
- レシピ詳細へ遷移
- 新規作成へ遷移

### 5. レシピ詳細

レシピの材料・分量・作り方を確認できます。

表示項目：

- レシピ名
- カテゴリ
- 説明
- 基準量
- 仕込み量
- 材料一覧
- 作り方
- 注意点
- アレルゲン
- 原価情報

重要方針：

- 材料セクションには原価情報を表示しない
- 材料欄は「作るための情報」に集中する
- 原価情報は「原価情報」セクションに集約する

### 6. 材料・分量・単価登録

材料を登録できます。

材料登録項目：

- 材料名
- 仕入先
- メモ
- 原価計算モード
- 仕入数量
- 仕入単位
- 仕入価格
- 使用単位
- 換算情報

### 7. 原価計算

MVPでは、材料ごとに原価計算モードを選べるようにします。

#### 原価計算モード

1. 原価計算しない
2. 仕入単位のまま計算
3. 使用単位に換算して計算

#### 例：原価計算しない

対象：

- 水
- 塩少々
- 飾り
- 適量の胡椒

#### 例：仕入単位のまま計算

卵：

- 1個 = 30円
- レシピで3個使用
- 原価 = 90円

#### 例：使用単位に換算して計算

ホールトマト：

- 1缶 = 180円
- 1缶 = 400g
- レシピで200g使用
- 原価 = 90円

MVPでやること：

- 原価計算ON/OFF
- 仕入単位のまま計算
- 1段階の簡易換算
- kg ⇔ g
- L ⇔ ml
- 缶 → g
- 袋 → g
- 本 → ml

MVPでやらないこと：

- 歩留まり
- 廃棄率
- 加熱後重量
- 複数段階換算
- 在庫連動

### 8. 今日の仕込み一覧

ホワイトボードの代替として、今日の仕込み一覧を表示します。

表示項目：

- 日付
- 未着手
- 作業中
- 完了
- 仕込みカード

仕込みカード：

- レシピ名
- 予定数量
- 単位
- ステータス

例：

- トマトソース 3バッチ
- プリン 20個
- ドレッシング 1L

### 9. 仕込みタスクの完了

仕込みタスクのステータスを変更できます。

ステータス：

- 未着手
- 作業中
- 完了

操作：

- 作業中にする
- 完了にする
- 未着手に戻す

MVPでは、ドラッグ操作は使わず、タップ操作を基本にします。

### 10. スマホ・タブレット対応

対応方針：

- スマホ：下部ナビ
- タブレット横：120px固定サイドバー
- PC：固定サイドバー

タブレット横向きは、厨房に置いて見る用途を重視します。

## MVP対象外

MVPでは以下を実装しません。

- 決済
- Stripe Checkout / Billing
- POS連携
- 複数店舗管理
- 在庫自動減算
- 高度な発注管理
- AI自動分類
- 栄養計算
- HACCP帳票
- 店舗端末管理
- 詳細な仕込みログ
- 自動期限アラート
- 原価の歩留まり計算
- 廃棄率計算

## 主要なバリデーション

### レシピ

- レシピ名は必須
- 基準量は0より大きい
- 基準単位は必須
- 販売価格は任意
- 販売価格が未設定の場合、原価率は表示しない

### 材料

- 材料名は必須
- 原価計算モードは必須
- 原価計算しない場合、価格情報は任意
- 仕入単位のまま計算する場合、仕入数量・仕入単位・仕入価格が必須
- 換算して計算する場合、仕入情報と換算情報が必須

### レシピ材料

- 材料選択は必須
- 使用量は0より大きい
- 単位は必須

### 仕込みタスク

- 日付は必須
- レシピは必須
- 予定数量は0より大きい
- 単位は必須
- ステータスは必須

## 権限方針

MVPでは `owner` / `staff` の2権限で最小限の操作範囲を分けます。

基本方針：

- 認証済みユーザーのみ利用可能
- すべてのデータは `shop_id` で分離する
- APIでは、フロントから渡された `shop_id` を信用しない
- サーバー側でログインユーザーの所属店舗に基づいて絞り込む
- ownerはレシピ、材料、カテゴリ、単位、店舗情報を作成・編集できる
- staffはレシピ、材料、カテゴリ、単位を参照でき、Prep Todayの仕込みタスクとメモを操作できる
- staffは自分の表示名を編集できる
- staffはレシピ、材料、カテゴリ、単位、店舗情報を作成・編集できない

将来方針：

- Staffには原価情報を非表示にできる

## エラー時の基本方針

エラー時は、ユーザーが次に何をすればよいか分かる表現にします。

例：

- 保存に失敗しました。もう一度お試しください。
- 入力内容を確認してください。
- ログインが必要です。
- このレシピは見つかりませんでした。
- 原価計算に必要な換算情報が不足しています。

基本方針：

- 技術的なエラー文をそのまま出さない
- 保存失敗時は入力内容をできるだけ保持する
- 認証切れの場合はログイン画面へ誘導する

## リリース前に確認すること

MVPリリース前の確認項目：

- ログインできる
- ログアウトできる
- 自店舗のデータだけ見える
- レシピを作成できる
- レシピを編集できる
- レシピ一覧で検索できる
- レシピ詳細で材料と作り方が見やすい
- 材料を登録できる
- 原価計算モードを選べる
- レシピ全体の材料原価が表示される
- 今日の仕込みを作成できる
- 仕込みタスクを完了にできる
- スマホで主要画面が使える
- タブレット横向きで見やすい
- 戻るボタンで直前画面に戻れる
- 材料欄に余計な原価情報が混ざっていない
