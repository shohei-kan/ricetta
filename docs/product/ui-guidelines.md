# Ricetta UI Guidelines

## 目的

Ricetta のUI方針をまとめる。

このドキュメントは、Figmaワイヤー、フロントエンド実装、Codex作業指示でUIの判断がブレないようにするためのものです。

Ricetta は「小さな飲食店のための、レシピ台帳。」をコンセプトにした、小規模飲食店向けレシピ管理SaaSです。

UIでは、業務システムらしい正確さよりも、**厨房・仕込み場で迷わず使えること**を優先します。

---

## UIコンセプト

Ricetta のUIは、以下を目指します。

```text
Notionより現場向け
Excelより見やすい
紙より探しやすい
ホワイトボードより残る
大手業務システムより軽い
```

大事にすること：

- 小規模飲食店向け
- 清潔感
- 柔らかい業務アプリ感
- 厨房タブレットで見やすい
- タップしやすい
- 文字で分かりやすい
- 情報を詰め込みすぎない
- 現場で迷わない
- 登録画面は重く見せすぎない

避けること：

- 大企業向け業務システムのような硬さ
- アイコンだけに頼るUI
- 細かすぎる情報表示
- ドラッグ前提の操作
- 原価情報を材料欄に混ぜる
- 初期MVPから高機能に見せすぎること

## デバイス別の方針

Ricetta は、スマホ・タブレット・PCで使う想定です。

### スマホ

主な用途：

- レシピ確認
- 今日の仕込み確認
- 簡単なステータス変更
- 軽い修正

UI方針：

- 下部ナビ
- 1カラム
- 縦スクロール
- カードは大きめ
- 操作はタップ中心

### タブレット横向き

主な用途：

- 厨房・仕込み場での閲覧
- 今日の仕込み確認
- レシピ詳細確認
- 材料と作り方の同時確認

UI方針：

- 横向き前提
- 120px固定サイドバー
- メイン領域を広く使う
- 材料と作り方をなるべく1画面で見せる
- タップしやすい余白
- 文字はやや大きめ

### PC

主な用途：

- レシピ登録
- 材料登録
- 原価確認
- 設定管理

UI方針：

- タブレット横向きと同じく固定サイドバー
- フォームは読みやすい幅に制限する
- 大画面でも横に伸びすぎない
- 入力作業しやすいレイアウトにする

## ナビゲーション方針

### スマホ

スマホでは下部ナビを使います。

項目：

```text
ホーム
仕込み
レシピ
材料
```

設定は、ヘッダーやメニュー内でも可とします。

### タブレット横・PC

タブレット横・PCでは、左固定サイドバーを使います。

仕様：

- 幅：約120px
- 常時表示
- 開閉しない
- テキストのみ
- カード型
- アイコンなし
- 現在地を明確に表示

項目：

```text
ホーム
仕込み
レシピ
材料
設定
```

### サイドバーの見た目

サイドバーは、主張しすぎず、でも迷わないようにします。

方針：

- テキストのみ
- 文字は大きめ
- 各項目はカード/ボタン風
- 選択中カードは淡いアクセント背景
- 選択中は文字を少し濃くする
- 店舗名は下部に控えめに表示

表示例：

```text
Ricetta

[ ホーム ]
[ 仕込み ]
[ レシピ ]
[ 材料 ]
[ 設定 ]

〇〇食堂
owner
```

## 戻るボタン

詳細・編集系の画面には、戻るボタンを置きます。

目的：

- 直前に見ていた画面へ戻る
- 一覧の検索条件やスクロール位置を保つ
- サイドバー遷移で文脈が切れるのを防ぐ

対象画面：

- Recipe Detail
- Recipe Edit
- Ingredient Form
- Settings 下層画面

表示：

```text
← 戻る
```

戻る例：

```text
Recipe List → Recipe Detail → 戻る → Recipe List
Prep Today → Recipe Detail → 戻る → Prep Today
Recipe Detail → Recipe Edit → 戻る → Recipe Detail
```

サイドバーは大きな画面移動、戻るボタンは直前の文脈へ戻るために使います。

## 画面別UI方針

## 01_Login

### 目的

Ricettaにログインする入口。

### 方針

- シンプル
- 中央寄せ
- ブランド名とコピーを見せる
- 入力欄は大きめ
- 余計な導線を増やしすぎない

表示例：

```text
Ricetta
小さな飲食店のための、レシピ台帳。

メールアドレス
パスワード

ログイン
```

---

## 02_Dashboard

### 目的

ログイン後に最初に開く「今日の現場」画面。

単なるホーム画面ではなく、朝一番に開いて今日やることを確認する画面です。

### 優先する情報

1. 今日の仕込み
2. 次にやること
3. 期限注意
4. よく使うレシピ
5. クイックアクション
6. ミニサマリー

### タブレット横レイアウト

2カラム構成を基本にします。

左カラム：

- 今日の仕込みサマリー
- 次にやること
- 今日の仕込みを見るボタン

右カラム：

- クイックアクション
- よく使うレシピ
- 期限注意
- ミニサマリー

### 方針

- 「今日なにをするか」がすぐ分かる
- 仕込みボードへの導線を一番強くする
- 余白はあるが、スカスカにしない
- 現場のホワイトボード代替感を出す

---

## 03_Prep_Today

### 目的

今日の仕込みを確認・更新する画面。

ホワイトボードに書いていた「今日の仕込み」を置き換えます。

### ステータス

```text
未着手
作業中
完了
```

内部値：

```text
todo
doing
done
```

### 操作方針

- ドラッグしない
- タップで操作する
- カードをタップすると操作モーダルを開く
- 操作はシンプルにする

### 仕込みカード

表示するもの：

- レシピ名
- 予定数量
- 単位

例：

```text
トマトソース
3バッチ
```

表示しないもの：

- 原価
- 詳細すぎるメモ
- 複雑なステータス

### タブレット横レイアウト

3カラム構成。

```text
未着手 | 作業中 | 完了
```

### スマホレイアウト

縦に並べる。

```text
未着手
カード一覧

作業中
カード一覧

完了
カード一覧
```

---

## 04_Prep_Action_Modal

### 目的

仕込みカードをタップしたときの操作メニュー。

### 表示項目

- レシピ名
- 予定数量
- レシピを見る
- 作業中にする
- 完了にする
- 未着手に戻す
- キャンセル

### 方針

- ボタンは大きく
- 選択肢を増やしすぎない
- スマホでは下から出るアクションシート風
- タブレットでは中央モーダルでも可

---

## 05_Recipe_List

### 目的

レシピを探して開く画面。

### 表示項目

- 検索欄
- カテゴリフィルター
- レシピカード
- 新規作成ボタン

### レシピカード

表示するもの：

- 写真
- レシピ名
- カテゴリ
- 基準量

例：

```text
トマトソース
仕込み
基準：1バッチ
```

### 方針

- 写真があると探しやすい
- ただし写真を主役にしすぎない
- レシピ名を大きく読む
- カードはタップしやすく

---

## 06_Recipe_Detail

### 目的

レシピを現場で確認する中心画面。

### 優先順位

1. レシピ名
2. 仕込み量
3. 材料
4. 作り方
5. 注意点
6. 原価情報

### 材料セクション

材料欄は「作るための情報」に集中します。

表示するもの：

- 材料名
- 使用量
- 単位

表示しないもの：

- 材料ごとの原価
- 単価
- 仕入情報
- 換算情報

例：

```text
ホールトマト　6缶
玉ねぎ　　　　900g
にんにく　　　30g
オリーブオイル　180ml
塩　　　　　　36g
```

### 原価情報セクション

原価情報は専用カードに集約します。

表示例：

```text
原価情報
材料原価：480円
販売価格：1,200円
原価率：40%
粗利：720円
```

販売価格が未設定の場合：

```text
材料原価：480円
販売価格：未設定
原価率：-
```

### 方針

- 材料と原価を混ぜない
- 厨房で見る画面として読みやすく
- タブレット横では材料と作り方をなるべく同時表示
- 原価情報は管理者向けなので控えめ

---

## 07_Recipe_Edit

### 目的

レシピを作成・編集する画面。

### セクション

- 基本情報
- 材料
- 作り方
- 管理情報

### 基本情報

- レシピ名
- カテゴリ
- 説明
- 完成写真
- 基準量
- 基準単位

### 材料

- 材料選択
- 使用量
- 単位
- 材料追加

材料入力欄にも原価情報を大きく表示しません。

原価は、必要に応じて「原価プレビュー」カードに集約します。

### 作り方

- 工程番号
- 作業内容
- 工程写真
- 工程追加

### 管理情報

- アレルゲン
- 販売価格
- 注意点
- メモ
- 原価プレビュー

### 方針

- 入力項目をセクションで分ける
- フォームを重く見せすぎない
- 保存ボタンを見つけやすく
- スマホでは1カラム
- タブレット横・PCでは2カラムも可

## カード設計

RicettaではカードUIを多用します。

対象：

- Dashboardのサマリー
- 仕込みカード
- レシピカード
- 設定カード
- 原価情報カード

方針：

- 角丸
- やわらかい背景
- 影は控えめ
- 文字は読みやすく
- タップ領域を広く
- カード内に情報を詰め込みすぎない

---

## フォーム設計

### 共通方針

- 1項目ずつ分かりやすく
- ラベルを必ず表示
- 必須項目を明確にする
- 入力例を出す
- エラーは項目の近くに表示
- 保存ボタンは見つけやすく

### 数値入力

対象：

- 基準量
- 使用量
- 仕入数量
- 仕入価格
- 予定数量

方針：

- 0以下は基本エラー
- 小数対応
- 単位とセットで見せる

### セレクト

対象：

- カテゴリ
- 単位
- 材料
- 原価計算モード

方針：

- 代表値はプルダウン
- ない場合は追加できる
- ただしMVPでは追加導線を簡易にしても可

---

## 原価計算UI

### 原価計算モード

材料ごとに3種類。

```text
原価計算しない
仕入単位のまま計算
使用単位に換算して計算
```

### 表示方針

Ingredient Formでは、説明付きのカードまたはラジオで選択します。

短い説明にする。

例：

```text
計算しない
水・飾りなど

そのまま計算
1個30円 → 3個使用

換算して計算
1缶180円 / 1缶400g
```

### Recipe Detail

材料欄には原価を出さない。

### Recipe Edit

材料行には原価を大きく出さない。  
必要なら「原価プレビュー」カードに集約する。

## 色・余白・文字サイズ

### 色

具体的なカラーコードはFigmaで確定後に追記します。

方向性：

- 白〜生成り
- 淡いベージュ
- 淡いグリーン
- 濃いグレー文字
- 注意表示は強すぎない色
- 期限切れだけ強めの警告色

### 余白

方針：

- 厨房で押しやすい余白
- ただしタブレット横では間延びしない
- カード間は広すぎない
- フォームはセクションごとに余白を取る

### 文字サイズ

方針：

- レシピ名は大きめ
- 仕込みカードの文字は大きめ
- サイドバーの文字は読みやすく
- 補助情報は小さくしてよい

目安：

```text
サイドバー：16〜18px
カードタイトル：18〜22px
本文：14〜16px
補助テキスト：12〜14px
```

---

## ローディング・空状態・エラー

### ローディング

- 大げさにしない
- カードのスケルトン表示でも可
- 保存中はボタンをdisabledにする

### 空状態

例：

```text
レシピがまだありません。
最初のレシピを作成しましょう。
```

```text
今日の仕込みはまだありません。
仕込みを追加しましょう。
```

### エラー

方針：

- 技術的な文言を出さない
- 何をすればよいか分かる
- 入力内容は消さない

例：

```text
保存に失敗しました。もう一度お試しください。
入力内容を確認してください。
ログインが必要です。
```

## やらないUI

MVPでは以下のUIは使わない、または後回しにします。

- ドラッグ&ドロップで仕込みカードを移動
- 開閉式サイドバー
- アイコンだけのナビ
- 高度なダッシュボードグラフ
- 複雑なフィルター
- 原価内訳を材料欄に常時表示
- スタッフ別の複雑な権限UI
- Stripe請求画面
- POS連携画面
- 在庫管理画面

---

## 実装時の優先順位

UI実装は以下の順で進めます。

```text
1. 共通レイアウト
2. サイドバー / 下部ナビ
3. Dashboard
4. Prep Today
5. Prep Action Modal
6. Recipe List
7. Recipe Detail
8. Recipe Edit
9. Ingredient List
10. Ingredient Form
11. Settings
12. 空状態 / エラー / ローディング
```

## 最重要方針

RicettaのUIで迷ったら、以下を優先します。

```text
現場で迷わないか
材料と作り方が読みやすいか
今日の仕込みがすぐ分かるか
MVPを大きくしすぎていないか
```

MVPのゴールは、以下の体験を成立させることです。

```text
小さな飲食店が、
レシピ台帳と今日の仕込みボードを、
ひとつのアプリで使えるか。
```
