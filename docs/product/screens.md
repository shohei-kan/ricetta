# Ricetta Screens

## 画面一覧

MVPで扱う画面は以下です。

| ID | 画面名 | 目的 |
|---|---|---|
| 01_Login | ログイン | アプリに入る |
| 02_Dashboard | ダッシュボード | 今日の現場を確認する |
| 03_Prep_Today | 今日の仕込み | 仕込み予定を確認・更新する |
| 04_Prep_Action_Modal | 仕込み操作モーダル | 仕込みカードの操作を選ぶ |
| 05_Recipe_List | レシピ一覧 | レシピを探す |
| 06_Recipe_Detail | レシピ詳細 | 材料・作り方・原価を確認する |
| 07_Recipe_Edit | レシピ作成/編集 | レシピを登録・編集する |
| 08_Ingredient_List | 材料一覧 | 材料マスターを探す |
| 09_Ingredient_Detail | 材料詳細 | 仕入・換算・単価を確認する |

| 12_Account | アカウント | 店舗情報・自分の情報・ログアウトを扱う |

補助画面：

- Category Settings
- Unit Settings

## 共通UI方針

### ナビゲーション

スマホ：

- 下部ナビ
- ホーム / 仕込み / レシピ / 材料 / 設定
- 各項目はLucideアイコンと小さいラベルを組み合わせ、省スペースでも意味が分かるようにする
- 下部ナビはDashboard、今日の仕込み、レシピ一覧、材料一覧、設定で表示する
- 詳細・作成・編集・Accountでは作業領域を優先して下部ナビを非表示にする
- 上部ヘッダーは固定せず、Ricettaロゴとアカウントアイコンだけを表示する
- 設定は重複を避け、上部ヘッダーではなく下部ナビから開く

タブレット横・PC：

- 左固定サイドバー
- 幅は約120px
- Lucideアイコン + テキスト
- カード型
- 常時表示

サイドバー項目：

- ホーム
- 仕込み
- レシピ
- 材料
- 設定

サイドバー下部には、アカウントアイコンと`アカウント`だけをまとめた控えめな `/account` 導線を表示します。Shop名と権限はDashboard上部で確認します。

### 戻るボタン

詳細・編集系の画面には、左上に「← 戻る」を表示します。

目的：

- 一覧のスクロール位置や検索状態を保ったまま戻る
- 直前に見ていた画面へ戻る
- サイドバー遷移と役割を分ける

戻る導線の例：

- Recipe List → Recipe Detail → 戻る → Recipe List
- Prep Today → Recipe Detail → 戻る → Prep Today
- Recipe Detail → Recipe Edit → 戻る → Recipe Detail

### フォーム入力

アプリ内のtextareaは、共通の自動伸縮textareaを使います。空欄や1行の内容では1行表示を基本にし、既存値の初期表示時と入力時に内容量へ合わせて高さを伸ばします。入力欄内の不要な縦スクロールは避け、枠線・角丸・色味は各フォームの既存トーンを維持します。

### Figmaワイヤー向けメモ

タブレット横では2カラム構成にします。

左カラム：

- 今日の仕込みサマリー
- 次にやること
- 今日の仕込みを見るボタン

右カラム：

- サマリー
- 期限注意

Dashboardでは「今日何をするか」が最初に分かることを優先します。

Dashboardの「今日の仕込み」サマリーと「次にやること」は、Prep Todayと同じ表示対象を使います。未完了の `todo` / `doing` は予定日に関係なく表示し、`done` は今日完了したタスクだけを当日中表示します。

「次にやること」は、作業中 → 未着手の順に表示します。作業中カードは黄色系、未着手カードはオレンジ系の淡い背景とバッジにし、状態が一目で分かるようにします。

## 03_Prep_Today

### 目的

ホワイトボードに書いていた「今日の仕込み」を置き換える画面です。

仕込みタスクをステータス別に表示します。

### 主な表示項目

- 今日の仕込み
- 日付
- ステータス別summary
- 未着手
- 作業中
- 完了
- 仕込みカード
- 未着手カラムの仕込みを追加ボタン
- 仕込み追加モーダル
- 3カラム下部の軽量メモ

未完了の `todo` / `doing` は予定日に関係なく表示し続けます。`done` は今日完了したタスクだけを表示します。持ち越しラベルや優先度表示はMVPでは追加しません。

### 仕込みカードの表示項目

- レシピ名
- 予定数量
- 単位
- メモ
- 完了時刻

仕込みカードは一覧性を優先して余白を抑えます。操作ボタンは常に3カラム横並びにします。

- 未着手：詳細 / 開始 / 完了
- 作業中：詳細 / 未着手 / 完了
- 完了：詳細 / 未着手 / 作業中

メモが空の場合はメモ欄を表示しません。メモがある場合も1行を基本にして、カードの縦幅を増やしすぎないようにします。

スマホでは未着手 / 作業中 / 完了カラムの高さを中身に合わせ、カードが少ない場合に大きな下部余白を残さないようにします。PC / タブレット横ではカンバン風の3カラム感を維持します。

例：

- トマトソース 3バッチ
- プリン 20個
- カレーソース 2バッチ

### 主な操作

- レシピを選んで仕込みを追加
- レシピ詳細を開く
- 作業中にする
- 完了にする
- 未着手に戻す

未着手カラムの「＋ 仕込みを追加」からモーダルを開き、レシピ、予定数量、予定単位、メモを入力します。レシピ選択時に基準量と基準単位を初期値にし、予定日は今日、statusは `todo` として保存します。作成成功後は一覧を再取得してモーダルを閉じます。

モーダルは中央の白系カード、薄いoverlay、角丸、薄い枠線で表示します。キャンセル、閉じるボタン、Esc、overlayクリックで閉じ、閉じた際はフォームstateを破棄します。

仕込み3カラムの下には、ホワイトボード的な軽量メモを横長カードで表示します。同じメモカード内で未チェックメモを上、今日チェック済みメモを下に分けます。未チェックメモは作成日に関係なくチェックされるまで残し、チェックすると今日中は「チェック済み」エリアに薄く表示します。チェック済みメモを再度クリックすると未チェックへ戻せます。昨日以前にチェック済みのメモは通常表示から外します。`＋ 追加` でメモを追加し、入力時は過去メモから履歴候補を表示します。カテゴリ、期限、担当者、優先度はMVPでは追加しません。

### UI方針

- ドラッグ操作は使わない
- タップ操作を基本にする
- カードは大きめ
- 厨房タブレットで押しやすくする
- 「未完了の仕込みと、今日完了した仕込みを表示します。」と簡潔に説明する

### Figmaワイヤー向けメモ

スマホ：

- ステータスごとの縦リスト

タブレット横：

- 3カラム構成
- 未着手 / 作業中 / 完了
- 未着手カラムヘッダー右側に小さい＋ボタン
- 3カラム下に横長のメモカード

スマホの未着手セクションでは、ヘッダー下に押しやすい「＋ 仕込みを追加」を表示します。
メモカードは3カラム下に縦方向で自然に配置します。

## 06_Recipe_Detail

### 目的

レシピを現場で確認する中心画面です。

材料・分量・作り方・注意点を見やすく表示します。

### 主な表示項目

- 戻るボタン
- レシピ名
- カテゴリ
- 完成写真
- 説明
- 基準量
- 仕込み量
- 材料
- 作り方
- 注意点
- アレルゲン
- 原価情報
- 編集ボタン

### 表示切り替え

`lg` 未満ではURLを変更せず、画面内のタブで次の3表示を切り替えます。

- 概要：説明、owner向け編集導線、原価情報、注意点 / メモ、アレルゲン
- 材料：材料名、数量、単位、材料メモ
- 作り方：手順番号、作業内容、工程メモ

レシピ名、カテゴリ、基準量 / 基準単位はタブ上部に表示します。タブは左右に余白を持つセグメントコントロール風とし、選択中は淡い背景と枠で明確にしつつ、主操作より強く見せません。タブはstickyにせず、材料や手順と一緒に通常スクロールします。

タブはタップに加えて横スワイプでも切り替えます。左スワイプで次、右スワイプで前へ移動し、先頭・末尾では停止します。横50px以上かつ横移動が縦移動より大きい場合だけ反応させ、材料一覧などの縦スクロールを妨げないようにします。

`lg` 以上ではタブを非表示にし、次の優先順ですべての情報を一覧表示します。

- 上部カード：カテゴリ、レシピ名、基準量 / 単位、説明
- 上部操作バー：戻る（左）、編集（右）
- 中段2カラム：材料、作り方
- 下段3カラム：原価情報、注意点 / メモ、アレルゲン

操作ボタンは上部カードの上で戻るボタンと同じ高さに配置し、`lg`以上では右寄せで横並びにします。狭い画面では窮屈にならないよう折り返します。

### 材料セクション

材料セクションには、原価情報を表示しません。
カードを重ねず区切り線中心のコンパクトなリストとし、厨房で読める文字サイズを保ちながら1画面の表示件数を増やします。
材料メモは初期状態で非表示にし、メモが1件以上ある場合だけ「下ごしらえメモを表示 / 隠す」で切り替えます。

表示するもの：

- 材料名
- 使用量
- 単位

例：

- ホールトマト 6缶
- 玉ねぎ 900g
- にんにく 30g
- オリーブオイル 180ml
- 塩 36g

### 原価情報セクション

原価情報は専用カードに集約します。

表示例：

- 材料原価：480円
- 販売価格：1,200円
- 原価率：40%
- 粗利：720円

販売価格が未設定の場合：

- 材料原価：480円
- 販売価格：未設定
- 原価率：-

### 主な操作

- 戻る
- 仕込み量変更
- 編集へ遷移
- 原価情報確認

編集導線はownerのみ表示し、staffは閲覧のみとします。

MVP frontendではRecipe Detailを確認・編集に集中させます。仕込み追加と進捗管理はPrep Todayへ集約します。材料欄には原価情報を混ぜず、原価は専用カードに集約します。

### Figmaワイヤー向けメモ

優先表示順：

1. レシピ名
2. 仕込み量
3. 材料
4. 作り方
5. 注意点
6. 原価情報

スマホ・タブレット横・PCのすべてで、必要な情報だけをタブ内に表示して縦方向の長さを抑えます。

## 07_Recipe_Edit

### 目的

レシピを作成・編集する画面です。

### 主な表示項目

- 戻るボタン
- 保存ボタン
- 基本情報
- 材料
- 作り方
- 管理情報

### 基本情報

- レシピ名
- カテゴリ
- 説明
- 完成写真
- 基準量
- 基準単位

### 材料

- 材料選択
- 使用量
- 単位
- 材料追加ボタン

材料行は、`md`以上では材料名を可変幅で最も広く、使用量を約112px、単位を約104pxで並べます。メモはその下の全幅行に置きます。スマホでは自然な縦並びにします。

編集時の使用量はAPIのdecimal文字列から不要な末尾ゼロだけを除いて表示します（`600.00` → `600`、`12.50` → `12.5`）。保存時のAPI形式は変更しません。

材料行の削除はカード右上の控えめな×ボタンで行い、`aria-label="この材料行を削除"` を付けます。
×を押した際は「この材料行を削除しますか？」と確認し、OKの場合だけフォームstateから削除します。

材料追加は背景・枠線を持たない控えめなオレンジの「＋ 追加」で行います。

材料入力エリアには、原価情報を大きく表示しません。

原価は、必要に応じて原価プレビューカードに集約します。

### 作り方

- 工程番号
- 作業内容
- 工程写真
- 工程追加ボタン

工程はPC / タブレット / スマホすべてで1工程1カードの縦並びにします。工程番号をカード上部へ表示し、全幅の作り方入力、その下にメモ入力を配置します。

工程カードは材料カードとトーンを揃えた白背景とし、工程追加は背景・枠線を持たない控えめなオレンジの「＋ 追加」で行います。

作り方と工程メモは、共通の自動伸縮textareaを使います。空欄や1行の内容では1行表示を基本とし、長文では入力欄内の縦スクロールを避けるよう自然に伸ばします。

工程削除はカード右上の`aria-label="この工程を削除"`付き×ボタンで行い、「この工程を削除しますか？」の確認後、OKの場合だけ削除します。

### 管理情報

- アレルゲン
- 販売価格
- 注意点
- メモ
- 原価プレビュー

### 主な操作

- レシピ保存
- 材料追加
- 材料削除
- 工程追加
- 工程削除
- 戻る
- キャンセル

### Frontend実装方針

- `/recipes/new` で新規作成する
- `/recipes/:id/edit` で編集する
- Category / Unit / Ingredient はAPIから取得する
- Ingredientを選択したとき、可能ならIngredientの使用単位を材料行のUnitに自動設定する
- 工程番号は保存時に表示順で `1, 2, 3...` と再採番する
- 編集保存時は現在フォーム上にある材料行・工程行をpayloadに含め、backendのnested replacement方針で全置き換えする
- 空の材料行・工程行は送信前に除外する
- Recipe削除UI、画像アップロード、材料ごとの原価内訳表示は後続フェーズに残す

## 10_Ingredient_Edit

### 目的

材料を新規作成・編集する画面です。

### 主な表示項目

- 戻るボタン
- 材料名

### cost_modeごとの表示

`none`:

- 材料名
- 仕入先
- メモ
- 原価計算モード

`same_unit`:

- 仕入数量
- 仕入単位
- 仕入価格
- 使用単位

MVPでは、仕入単位を選ぶと使用単位も同じ値に自動設定します。

`conversion`:

- 仕入数量
- 仕入単位
- 仕入価格
- 使用単位
- 換算元数量
- 換算先数量

MVPでは、換算元単位は仕入単位、換算先単位は使用単位に自動設定します。

### 主な操作

- 保存
- キャンセル
- 戻る

保存失敗時は入力内容を消さず、frontend validationとbackend validation errorを表示します。

## 11_Settings

### 目的

店舗やレシピ台帳に関する設定を管理する画面です。

### MVPで扱う設定

- レシピカテゴリ
- 単位

### 主な表示項目

#### レシピカテゴリ

- カテゴリ名
- 表示順
- 作成フォーム
- 編集ボタン
- 削除ボタン

#### 単位

- 単位名
- 種別
- 標準 / 店舗独自
- 作成フォーム
- 編集ボタン
- 削除ボタン

Unit種別：

- weight: 重量
- volume: 容量
- count: 個数
- custom: その他

### 主な操作

- カテゴリ追加
- カテゴリ編集
- カテゴリ削除
- 単位追加
- 単位編集
- 単位削除

### Frontend実装方針

- Category / Unitを1画面で管理する
- 管理フォーム、編集ボタン、削除ボタンはownerのみ表示する
- staffには現在のカテゴリ・単位一覧と、管理はオーナーのみである旨を表示する
- 編集UIは作成フォームが編集フォームに切り替わる簡易方式にする
- 成功後は一覧を再取得する
- 削除時は確認ダイアログを出す
- 標準Unitは編集・削除ボタンを表示しない
- ユーザー管理、請求設定はMVPでは扱わない

## 12_Account

### 目的

現在の店舗情報と自分の所属情報を確認・更新し、ログアウトする画面です。

### 主な表示項目

- 店舗名
- 業態
- メモ
- メールアドレス（表示のみ）
- 表示名
- 権限
- ログアウト

### 権限

- owner: 店舗情報と自分の表示名を編集できる
- staff: 店舗情報は閲覧のみ、自分の表示名は編集できる

### 導線

- PC / タブレット: サイドバー下部の店舗名・権限表示から遷移する
- スマホ: 上部ヘッダーの「アカウント」から遷移する
- ログアウトはAccountページ下部に配置する

メールアドレス変更、パスワード変更、複数店舗切り替えは今回扱わない。

## 画面設計の重要方針

- Dashboardは「今日の現場」を確認する画面
- Prep Todayはホワイトボード代替

- Recipe Editは管理・登録画面
- Ingredient Detailは材料マスター管理画面
- 材料欄に原価情報を混ぜない
- 原価情報は専用カードに集約する
- 戻るボタンで直前の文脈に戻れるようにする
- タブレット横向きでは120px固定サイドバーを使う
